# TDD 编写功能（红-绿-重构）

> 先写失败测试、再写最小实现、最后重构——新代码全程由测试驱动，收尾清掉冗余用例。

**技能名**：`tdd-write-feature` · 目录内只有 `SKILL.md`

## 什么时候用

- 用户说「TDD 编写」「先写测试再写代码」
- 要新增功能或修 bug，且希望走 test-first 路线

## 怎么用

本技能不含具体命令，两步：

1. **TDD 循环** —— 加载 `test-driven-development` 技能，按它的节奏执行：
   - **红**：先写一个会失败的测试
   - **绿**：写最小实现让它通过
   - **重构**：在测试保护下整理代码
2. **清理过时测试** —— 扫描测试文件，**删除**过时的测试用例。SKILL.md 明确列了三类：
   - 测试已删除的功能
   - 测试已重构掉的代码路径
   - 与其他测试重复且无增量价值的用例

出口：新代码由测试驱动完成，测试套件干净无冗余。

## 前置条件

- `test-driven-development` 技能已安装（Step 1 直接依赖它）
- 项目本地可运行测试

## 注意事项 / 已知坑

- 顺序不能倒：先有失败测试再写实现。跳过「红」直接写实现就不算 TDD。
- Step 2 的删除是**真删**，不是注释掉留作备用；但只在能确认「功能/代码路径确实已不存在」或「与别的用例重复且无增量价值」时才删。
- 本技能只负责写码与清场；功能做完后的整体验证用 `tdd-test-feature`。
- 详细步骤见 SKILL.md。
