# TDD 跑测试（验证与清场）

> 代码改完后跑通全部测试，并顺手删掉已经过时的测试用例——测试套件保持全绿且干净。

**技能名**：`tdd-test-feature` · 目录内只有 `SKILL.md`

## 什么时候用

- 用户说「跑测试」「TDD测试」「验证测试」
- 代码改动完成后、提交前的验证环节

## 怎么用

本技能不含具体测试命令，三步流程：

1. **运行测试** —— 加载 `test-driven-development` 技能，执行**全部**测试套件（具体命令由该项目与 `test-driven-development` 决定）。
2. **清理过时测试** —— 扫描测试文件，删除过时的测试用例。
3. **确认通过** —— 所有测试必须通过；有失败 → 修复 → 重新运行。

出口：全部测试通过，测试套件干净。

## 前置条件

- `test-driven-development` 技能已安装（Step 1 直接依赖它）
- 项目本地可运行测试（依赖、构建产物就绪）

## 注意事项 / 已知坑

- Step 2 是**删除**动作，不是注释或跳过：过时用例要真正移除。删之前确认它测的是确实不存在的功能/代码路径，别把「暂时失败」当成「过时」删掉。
- 「全部通过」是硬出口：有失败就是没完成，不允许带着红测试收尾。
- 本技能只跑测试与清场，不写新功能代码（写代码用 `tdd-write-feature`）。
- 与 `tdd-write-feature` 的区别：那个是 test-first 写码时用，这个是**已有改动**后验证时用。
- 详细步骤见 SKILL.md。
