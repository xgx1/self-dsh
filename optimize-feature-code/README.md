# 代码极简化优化（optimize-feature-code）

> 一条三阶段链路把代码里的过度工程榨干：先极简化、再收集技术债务、最后专门复审一遍过度工程。

## 什么时候用

用户说出这些词时触发：

- 「优化代码」
- 「极简化」
- 「ponytail 优化」

## 怎么用

本技能**没有 shell 命令**，它是一段技能编排：按顺序加载并执行下面三个技能。

### Step 1：极简化 —— 加载 `ponytail`

全仓或针对性极简化：

- 删除无用代码、过度抽象
- 用标准库替代自定义实现
- 遵循 YAGNI 原则

### Step 2：收集技术债务 —— 加载 `ponytail-debt`

收集代码里所有 `ponytail:` 注释，生成技术债务清单。

### Step 3：过度工程复审 —— 加载 `ponytail-review`

对优化后的代码做专门审查，找出遗漏的过度工程。

## 出口标准

代码最简；技术债务已记录且可见。

## 前置条件

- 三个被编排的技能可用：`ponytail`、`ponytail-debt`、`ponytail-review`

## 注意事项 / 已知坑

- SKILL.md 只有阶段编排与各阶段职责，**每一步的具体做法以被加载的技能为准**（详细步骤见 `SKILL.md` 与这三个被引用的技能）。
- 三个阶段是有序的：先动手简化、再记录遗留、最后复审，不要跳过 Step 2 直接出结论——否则 `ponytail:` 留下的刻意简化会失去追踪。
