# 制定实现计划（make-feature-plan）

> 把「要做个什么」变成一份彻底清晰、用户点头的实现计划 + TODO 清单——靠「生成计划 → 深度追问 → 二轮头脑风暴 → 用户反馈」的循环收敛。

## 什么时候用

- 用户说：**制定计划**、**生成实现方案**、**做 TODO 清单**
- 需求已大致清楚，要落成可执行的实现步骤
- 不适用：需求还很模糊 → 先 `init-feature-dev` / `brainstorming`

## 操作流程

### Step 1：生成初始计划

- 加载 `writing-plans` —— 生成实现计划
- 生成 TODO 清单（`todo init`）

### Step 2：审查循环

直到用户确认「计划彻底清晰明确」前，循环执行：

```
┌─ 加载 grill-with-docs — 对计划进行深度询问
│    ↓
│   加载 brainstorming — 第二轮头脑风暴
│    ↓
│   用户审查并反馈
│    ↓
├─ 有模糊点？─→ 回到循环开头
│
└─ 清晰明确？─→ 退出循环
```

> 上面的流程图是 SKILL.md 原文照抄。

## 出口

计划彻底清晰明确、用户确认，TODO 清单已就绪。

## 前置条件

- 已安装 `writing-plans`、`grill-with-docs`、`brainstorming`（本机均已装）
- 用户在场参与多轮反馈——循环的退出条件就是用户确认

## 注意事项 / 已知坑

- 循环由**用户反馈驱动**，agent 不能自判「已清晰」就退出。
- SKILL.md 写的 TODO 生成命令是 ``todo init``；本机 `PATH` 里**当前没有 `todo` 命令**（实测），技能未给出替代命令，执行时以项目现有的 TODO 机制为准。
- SKILL.md 仅 32 行，未约定计划文件的落盘路径与格式；**详细步骤见 SKILL.md** 与被引用的 `writing-plans`。
