# 代码审查（review-feature-code）

> 对当前变更做双轴审查：一边看是否遵循项目编码规范（Standards），一边看是否匹配原始需求（Spec）。

## 什么时候用

用户说出这些词时触发：

- 「代码审查」
- 「review 代码」
- 「审查一下」

## 怎么用

本技能**没有 shell 命令**：触发后加载 `code-review` 技能，对变更执行双轴审查。

- **Standards**：代码是否遵循项目编码规范
- **Spec**：代码是否匹配原始需求 / PRD

两条轴各有独立的判断依据，审查产出应能分别回答这两个问题；具体的变更范围界定、审查执行方式由 `code-review` 技能定义。

## 出口标准

审查完成，问题已修复或已记录。

## 前置条件

- `code-review` 技能可用
- 存在可审查的变更（当前分支 / 工作区改动）

## 注意事项 / 已知坑

- SKILL.md 只有 17 行，仅规定「加载 `code-review` + 双轴含义 + 出口」，**详细的审查步骤见 `SKILL.md` 与 `code-review` 技能文档**，本 README 不做补充推断。
- 必须真正跑完 `code-review`，不要凭印象直接给审查结论。
- 出口是「修复或记录」二选一，不允许带着未落地的发现结束。
