# 生成开发总结

> 功能做完后产出四维度开发总结（做了什么 / 改了什么 / 生成了什么 / 学到了什么），为整条开发流程收尾。

**技能名**：`summarize-feature-work` · 目录内只有 `SKILL.md`

## 什么时候用

- 用户说「生成总结」「写开发总结」「做了什么总结」
- 功能开发流程走到最后一步、准备归档时

## 怎么用

本技能不含命令，两步：

1. **加载 `dev-docs`** —— 拿到 Docs/ 的排版与结构规范（禁序号、标题层级、wikilink、callout、tags、目录结构）。总结是 Obsidian 格式文档，格式以 `dev-docs` 为准，不自创。
2. **编写总结** —— 四个维度缺一不可：
   - **做了什么** —— 功能实现清单
   - **改了什么** —— 修改的文件和模块
   - **生成了什么** —— 新建的文件、文档、技能
   - **学到了什么** —— 经验教训和技术发现

出口：总结文档已生成，开发流程正式结束。

> 文档落在哪个目录、文件名是什么，SKILL.md 没有写死——按 Step 1 加载到的 `dev-docs` 规范决定。

## 前置条件

- 本次功能的实际改动已知（动过哪些文件/模块、新建了哪些产物）
- `dev-docs` 技能已安装

## 注意事项 / 已知坑

- 「学到了什么」最容易漏写。它和 `solidify-feature-lessons` 职责不同：这里只是**记录**，固化进记忆/技能/AGENTS.md 是那个技能的事，别在本技能里顺手改 AGENTS.md。
- 「生成了什么」指新建产物（文档、技能、脚本），「改了什么」指既有文件的修改，两者别混。
- 详细步骤见 SKILL.md。
