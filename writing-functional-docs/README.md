# 编写功能文档（行为说明书）

> 从已有代码库反向产出**玩家/用户视角**的功能文档：只写「做什么操作 → 出现什么效果」，不出现任何 API 与实现细节。

**技能名**：`writing-functional-docs` · 目录内只有 `SKILL.md`

## 什么时候用

- 为已有项目补写功能/行为文档，「分析现有功能写文档」
- 需要一份 QA 不看代码就能逐项验证的验证基准
- 设计图/需求与实现需要对齐盘点（差异 → 缺陷清单）

不适用：需求文档（写「应该怎样」）、技术清单（代码资产在哪）、API 参考。

## 怎么用

流程：**规范先行 → 代码挖行为 → 并行编写 → 缺陷排队 → 状态标注**；排版格式另由 `dev-docs` 管（写时两个技能同载）。

1. **规范先行（必须先做）** —— 先产出《功能文档编写规范》交用户改，定稿后才动手写。核心条款：一个系统一个目录 `功能/<系统名>/`、每篇只写一个功能点；每目录一份 `_概述.md`；单篇字段为操作/条件/效果/他人视角/边界/数值/状态；写玩家语言、禁 API、只写可观察行为；状态三值（已验证/待验证/疑似缺陷）。
2. **行为挖掘（只读代码）** —— 输入→行为映射、配置真值（资产 CDO 覆盖代码默认值）、可观察行为、旧文档加速度。二进制映射资产（如 UE IMC 的 uasset）必须结构化 dump：
   ```powershell
   # SKILL.md 给出的无头 dump 跑法（~15s，Windows 路径示例）
   UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script=<py> -unattended -nop4 -nullrhi
   ```
   只用 `rg --text` 扫 IMC 资产的按键名列表是不够的：IA↔按键配对因 import 表排序丢失，**必须**无头 dump。
3. **编写** —— 效果写全视觉/听觉/触觉通道；多人游戏必写他人视角；数值区分准确值与「约」；交叉引用用 wikilink。自查禁词零命中（正则见下）。
4. **缺陷排队（不边写边修）** —— 现状与设计不符记入集中 `缺陷.md`，不在文档阶段改代码。状态机：⬜待决定 → 📌方案已定待实施 → 🔧修复中 → ✅已修复 / ❌不修。
5. **并行分派（多系统时）** —— 每系统一个子 agent，一次批处理全发；主会话统一合并缺陷、去重、连续编号。
6. **验证与交付** —— 无法上机（VR/设备）时全部标「待验证」，交付用户/QA 逐条核对后改状态。

禁词自查正则在 SKILL.md 中给出（命中即不合格，仅 `缺陷.md` 与旧模块文档允许命中）：

```
UV?R[A-Z]\w+|\.cpp|Source/|/Game/|RPC|蓝图|对象池
```

## 前置条件

- `dev-docs` 技能已安装（排版规范）
- 可读的项目代码库；UE 项目还需可用的无头 `UnrealEditor-Cmd` 与 dump 脚本（`Saved/Temp/` 下，不进 git）
- 分析源 `Docs/检查/<系统>.md`（若有）只取「玩家可观察行为」，不照抄技术细节

## 注意事项 / 已知坑

- **项目特定配置**：SKILL.md 下半部分绑定某个 UE5 VR 项目——规范 `Docs/规范/功能文档编写规范.md`、缺陷台账 `Docs/功能/缺陷.md`、范例 `Docs/功能/武器系统/`、引擎路径 `C:/Users/Admin/Project/UnrealEngine`（Launcher 版缺 PICOOpenXR）、`DumpImcAdmin.py` / `DumpBp.py`（后者用前需 sed 改 Admin 路径）。换项目这些路径全要改。
- 用 `rg` 扫二进制输入资产后**猜**按键映射是头号错误——关联已丢失，必须 dump 实证。
- 边写文档边修缺陷会让范围爆炸；全部排队、最后统一决定。
- 把设计目标当现状写且不加 ⚠️ 标注 = 文档撒谎；设计图与代码冲突时按设计写并标注「当前版本与设计不一致」+ 缺陷条目。
- 本机无 VR 头显时，**禁止**把未亲验的条目标「已验证」。
- 批量编写模式已验证：12 系统 76 篇一次完成；子 agent 结果契约 `{system, docs[], defects[], uncovered}`，缺陷由主会话统一写入，agent 不写 `缺陷.md`。
