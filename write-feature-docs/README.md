# 编写功能文档 / 设计文档

> 把功能细节写成结构化的 Obsidian 文档，落在 `Docs/` 下，并通过用户审核才收尾。

**技能名**：`write-feature-docs` · 目录内只有 `SKILL.md`

## 什么时候用

- 用户说「编写功能文档」「写设计文档」「更新文档」
- 功能实现后需要沉淀成 Docs/ 下的正式文档时

## 怎么用

本技能不含命令，三步，最后一步是**阻塞式审核门**：

1. **加载文档规范** —— 加载 `dev-docs`，拿到 Docs/ 排版与结构规范，共五项：
   - 序号禁止规范（标题、目录、列表）
   - Wikilink 双向链接
   - Callout 标注语法
   - 标签体系
   - 文件命名和目录结构
2. **编写文档** —— 按功能范围编写，严格遵循 Step 1 的规范。
3. **用户审核 ⏸️** —— **必须等待用户审核**：
   - 用户告知「通过」→ 完成
   - 有遗漏 → 用户告知修正内容 → 回到 Step 2

出口：功能文档审核通过。

## 前置条件

- `dev-docs` 技能已安装（排版与结构以它为准）
- 待写的功能范围明确

## 注意事项 / 已知坑

- Step 3 是硬门禁：不要写完就宣布完成，也不要在用户没回话时自己判定「通过」。
- 内容与排版分工：本技能正文只点名 `dev-docs`（管排版）；frontmatter 的 description 里写明「`dev-docs` 管排版、`writing-functional-docs` 管内容」——要写的是玩家/用户视角的行为说明书时，内容流程用 `writing-functional-docs`。
- 序号、wikilink、callout、tags 都是 `dev-docs` 的硬规范，违反即需返工；别凭习惯自创格式。
- 详细步骤见 SKILL.md。
