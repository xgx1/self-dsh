# 修复测试反馈的问题（fix-feature-issues）

> 用户测试后报上来的问题怎么修：先读反馈文档和 UnrealCli 日志报告，再按「诊断 → 修根因」的顺序处理。

## 什么时候用

- 用户说：**修复问题**、**修 bug**、**处理反馈**
- 一轮用户测试结束、反馈文档与日志报告已产出时
- 不适用：问题还没定位、需要先复现探索 → 可先单独跑诊断类技能

## 操作流程（三步）

### Step 1：获取问题清单

- 读取 `Docs/当前反馈问题.md` —— 用户反馈的问题列表
- 读取由 **UnrealCli 生成的最新日志报告**

### Step 2：诊断

对每个问题加载 `diagnose` 技能：**复现 → 缩小范围 → 假设 → 验证**。

### Step 3：修复

对**已诊断**的问题加载 `systematic-debugging` 技能：**定位根因 → 修复 → 验证**。

## 出口

所有已知问题已修复，等待下一轮用户测试验证。

## 前置条件

- 项目里存在 `Docs/当前反馈问题.md`（问题清单来源）
- 有 UnrealCli 产出的最新日志报告
- 被引用技能 `diagnose`、`systematic-debugging` 可用

## 注意事项 / 已知坑

- **顺序不能颠倒**：诊断（Step 2）在修复（Step 3）之前，禁止跳过诊断直接改代码。
- `diagnose` 是 SKILL.md 点名的技能，但本机 `~/.dsh/skills/` 下**当前没有名为 `diagnose` 的技能**（实测）；`systematic-debugging` 已安装。若确实缺失，先确认可用的诊断技能再继续。
- 本技能不含命令与脚本；`Docs/当前反馈问题.md` 与「UnrealCli 最新日志报告」的确切位置以项目实际为准。SKILL.md 仅 23 行，**详细步骤见 SKILL.md**。
