# 更新人工测试文档

> 修完 bug 之后，把「修了什么、哪些要重测、步骤和预期怎么变了」同步进已有的人工测试文档。

**技能名**：`update-manual-test-doc` · 目录内只有 `SKILL.md`

## 什么时候用

- 用户说「更新测试文档」「更新 QA 文档」
- 一轮问题修复完成后，原测试文档已经与现状对不上时

## 怎么用

本技能不含命令，两步：

1. **加载 `dev-docs`** —— 拿到 Docs/ 的排版与结构规范，更新内容按其格式写。
2. **更新测试文档** —— 更新内容必须包含四块：
   - **修复清单** —— 修复了哪些问题
   - **重新测试清单** —— 需要重新测试哪些功能
   - **变更的测试流程** —— 哪些测试步骤发生了变化
   - **新的预期结果** —— 修复后的正确行为

出口：人工测试文档已更新，开发者可按最新文档重新测试。

> 文档具体路径与文件名由项目现有测试文档决定，SKILL.md 未写死；详细步骤见 SKILL.md。

## 前置条件

- 已有一份人工测试文档可更新（新建文档用 `write-manual-test-doc`）
- 本轮修复清单与改动范围已知
- `dev-docs` 技能已安装

## 注意事项 / 已知坑

- 重点是**四块内容都要有**，尤其「重新测试清单」和「新的预期结果」——只列修复项、不写清哪些旧步骤作废，测试者会按过期步骤跑出假失败。
- 修完 bug 后旧预期可能整段失效，要显式改写而不是在文末追加一段「本次修复」了事。
- 与 `write-manual-test-doc` 的分工：那个从零写测试文档，这个只做修复后的增量对齐。
